# 헌법재판소 주요결정 페이지의 표제·판시사항·요지 — 페이지별 출처 순서와 표준판례 배지 링크

작성 2026-11-07 (브랜치 `claude/ccourt-page-summary-c526a3`). 사용자 요구: 같은 재판이 표준판례 페이지와 헌법재판소 주요결정 페이지에 함께 배치되면
표준판례 페이지는 지금처럼 표준판례 내용만 쓰되, 헌법재판소 주요결정 상세창에서는 **재판 전체를 조명하는 표제와 판시사항·요지**를 보여 주고,
보라색 "표준판례" 배지를 누르면 표준판례 페이지의 그 재판 상세창으로 넘어가게 한다.

## 1. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 출처 순서의 단위 | **페이지 그룹**(`tools/build_data.py` 의 `SUMMARY_PRECEDENCE`) — 특정 id 를 하드코딩하지 않는다 | 다른 세션이 2009~2019 결정 약 2,000건을 등록하면 표준판례와 겹치는 재판이 크게 늘고, 미수집 결정의 공식본이 뒤늦게 들어오므로 일반 규칙이어야 통합 후에도 그대로 적용된다 |
| 표준판례(`std-*`)·판례연구(`research-*`) | 표준판례 → 공식 → 편집 요약 (종전과 같음) | 단원(목차)에 맞춘 검증된 발췌가 학습 목적이다 |
| 최신판례 페이지 `ccourt`·`enbanc`·`annual` | **공식 → 표준판례 → 편집 요약** | 세 페이지 모두 재판을 선고연도·분야로 나열하며 재판 전체를 보여 주는 자리다. 표준판례 발췌는 그 책의 단원이 다루는 쟁점 일부만 담으므로(예: 2021헌마619 변호사 광고 규정 사건은 헌법 표준판례 145·497·498 배치가 각각 다른 쟁점만 발췌) 공식 판시사항·요지가 재판 전체를 조명한다. 사용자 요구는 헌법재판소 페이지였지만 전원합의체·법률신문 페이지도 같은 성격이어서 같은 규칙을 적용했다(영향: 전원합의체 195건, 법률신문 173건이 표준판례 발췌 대신 공식 요지를 보인다; 되돌리려면 `SUMMARY_PRECEDENCE` 한 줄). 판례연구는 목차 기반 수록본이라 표준판례 우선을 유지했다 |
| 배치별 덮어쓰기 | `python tools/add_cases.py set <id> --summary-source standard\|official\|auto` → 등록부 `summarySource`. 빌드는 그 출처를 맨 앞에 둔다 | 공식 요지가 재판 전체를 보여 주지 못하는 예외 배치(또는 반대로 표준판례 페이지에서 공식을 먼저 보일 배치)를 위해. `validate` 가 값을 검사한다 |
| 편집 요약의 순서·근거 | 편집 요약은 어느 페이지에서든 마지막. `editorial.basis {label, url, note, basedOn}` 에 근거 자료를 적고 화면은 "※ 편집 요약 — … 근거: <링크>" 로 표시 | 공식 판시사항·요지도 표준판례 출처도 없는 결정(현재 68건)을 위해. 공식본이 뒤늦게 수집되면 공식이 자동으로 앞선다(`test_page_summary_precedence.test_official_arriving_later_wins_over_editorial_without_registry_change`) |
| 표준판례 빈 배열 `[]` | 표준판례 차례에서만 그 필드를 비운다 | 종전 §1-3 규칙을 순서 안에서 그대로 유지 |
| 표준판례 배지 | 표준판례 페이지 밖의 배치 레코드에 `standardPlacements: [{id, page, subject, title, tocPath}]` (과목 순서 → 수록 순서). 상세창의 배지는 `<a class="badge standard" href="#/std-<과목>/<id>">`, 배치가 여럿이면 "표준판례 ①" "②" … 를 모두 링크로(툴팁·aria-label 에 "페이지 › 목차 › 제목"). 목록 항목 안(링크 안)에서는 종전처럼 표식(span)만 | 키보드(Tab + Enter)와 북마크 뷰(`#/bookmarks/<id>`)에서도 같은 링크가 동작한다 — `tools/test_standard_badge_ui.cjs` |
| 요약 탭 안내문 | 공식 요지를 보이는 배치에 표준판례 배치가 있으면 "이 재판은 표준판례에도 수록되어 있습니다. 단원에 맞춘 표준판례의 판시사항·요지: <링크>" | 배지를 모르는 사용자도 표준판례 수록본을 찾아가게 |
| 표제 | ccourt 배치의 제목은 배치별로 따로 두되(`set --title`), 표준판례 배치 제목은 바꾸지 않는다 | 같은 재판이라도 페이지에 따라 표제가 다를 수 있다는 요구 |

출처 표시: 공식 → "출처: 국가법령정보센터 공식 수록본" + 하단 "· 공식 판시사항·요지"; 표준판례 → "출처: 표준판례 · 판본 · 쪽 · 표준판례 수록본 우선";
보충 자료(사용자 제공·포털) → "출처: <label>"; 편집 요약 → "※ 편집 요약 — … 근거: <링크>". `summaryType`·`fieldSources`·`summaryPrecedence` 는 `data/schema.md` §4.

## 4. 편집 요약 작성 (공식 판시사항·결정요지도 표준판례 출처도 없는 ccourt 배치)

대상 68건(공식 판시사항·결정요지 없음: `.missing` 42건 + 전문만 수집된 26건) 가운데 **68건**을 등록했다(근거: 결정문 전문 26건, 헌법재판소 최근 주요결정 게시물 42건). 기존 편집 요약 12건(한 줄짜리 질문형)은 같은 형식으로 다시 썼다.

작업 방식(ultracode · Workflow `ccourt-editorial-summaries`, 2단계 파이프라인): ① 초안 — 결정문 전문(있으면 1차 근거)과 헌법재판소 게시물(사건개요·심판대상·결정주문·이유의 요지)을 읽고 law.go.kr 형식으로 번호 매긴 판시사항("…인지 여부(적극/소극)", "…한 사례")과 같은 번호의 결정요지(반대의견·별개의견은 "재판관 ○○○의 반대의견"으로 끝에), 심판대상조문을 작성; ② 검증 — 다른 에이전트가 근거 문서와 대조해 쟁점 누락·방향(적극/소극)·사실 충실성·형식·길이(판시사항 250자, 결정요지 900자)를 적대적으로 검사하고 고친 최종본을 냄(정정된 건 64건). 그 뒤 가져오기 스크립트가 번호·개수 일치·【 】·약칭·문장형 종결을 검사하고 `add_cases.py set <id> --editorial` 로 등록했다(`checked_editorial` 이 다시 검사). 근거는 `editorial.basis` 에 남긴다: 전문 기반은 `{label: '헌법재판소 결정문 전문(국가법령정보센터 수록본; 판시사항·결정요지 미게재)', url: law.go.kr 주소, basedOn: 'fulltext', note: 게시물 주소}`, 게시물 기반은 `{label: '헌법재판소 최근 주요결정 게시물', url: View.do 주소, basedOn: 'post'}`.

- **2018헌마456(cc-2018heolma456)**: 공식본이 없어(수집 때 선고일 2021-01-28/01-26 충돌) 헌재 페이지에서 표준판례 발췌(std-constitution-128)로 보인다. 세션 ④가 공식본을 확보하면 자동으로 공식이 앞선다.
- **편집 요약 68건은 모델이 근거 문서(결정문 전문 26건·헌재 게시물 42건)에서 작성·검증한 것**이다. 사용자 검토를 권하며, law.go.kr 이 판시사항·결정요지를 게재해 수집되면 공식이 자동으로 앞서므로 등록부의 `editorial` 을 지울 필요는 없다. 검증 단계에서 길이 제한 때문에 줄인 항목은 `editorial-report.json`(세션 scratchpad)에 기록돼 있다.
- **표준판례와 겹치지 않는 ccourt 배치 148건의 제목이 공식 사건명 그대로**(`titleIsCaseName`)다. 이번 검토 범위(겹치는 61건) 밖이라 바꾸지 않았다. 편집 요약 작업에서 에이전트가 제안한 제목은 §4 표에 있다(미적용).
- **전원합의체·법률신문 페이지도 공식 우선으로 바뀌었다**(각 195·173건이 표준판례 발췌 대신 공식 요지를 보임). 사용자가 헌재 페이지만 원하면 `SUMMARY_PRECEDENCE` 의 두 줄을 되돌리면 된다. 포털(사법정보공개포털) 수록본만 있는 전원합의체 배치는 종전처럼 `summaryType: mixed`(보충 자료) 로 집계되며 화면 출처는 "사법정보공개포털 …" 이다.
- `tools/test_web.py` 의 오프라인 저장 대기 시간(180초)은 코퍼스가 더 커지면 다시 늘려야 할 수 있다.
- 다른 세션 브랜치(①·②·④)와의 통합 검증은 상위 세션이 한다: 병합 뒤 `make validate data` → `python tools/check_ccourt_page_summary.py` 로 새 겹침·미수집을 확인한다.
