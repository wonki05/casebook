# 판례집 시안 v2 공통 사양 — design-d "판례집+시트", design-e "서가"

v1 사양(`spec/SPEC.md`)의 §4 타이포, §5 색, §6 공통 기능, §7 표기 규칙은 그대로 유효하다. 이 문서는 **바뀌는 것과 새로 추가되는 것**만 적는다.
두 시안 모두 **design-b(`src/design-b.html`)의 색·배경·조판을 기반**으로 한다(미색 종이, 가운데 열, 얇은 보라 상단선). design-c 의 시트 코드, design-a 의 사이드바 코드를 가져다 써도 좋다.

## 1. 페이지 구조 — 8 페이지 (`DATA.pages`)
```
pages: [
 {id:'std-constitution',   label:'헌법 표준판례',   short:'헌법',    section:'표준판례', group:'standard', subject:'constitution'},
 {id:'std-administrative', label:'행정법 표준판례', short:'행정법',  section:'표준판례', group:'standard', subject:'administrative'},
 {id:'std-civil',          label:'민법 표준판례',   short:'민법',    section:'표준판례', group:'standard', subject:'civil'},
 {id:'std-criminal',       label:'형법 표준판례',   short:'형법',    section:'표준판례', group:'standard', subject:'criminal'},
 {id:'annual', label:'분야별 주요판례', short:'주요판례', section:'최근 판례', group:'annual'},
 {id:'enbanc', label:'대법원 전원합의체', short:'전원합의체', section:'최근 판례', group:'enbanc'},
 {id:'ccourt', label:'헌법재판소 주요결정', short:'헌법재판소', section:'최근 판례', group:'ccourt'},
 {id:'laws',   label:'법령', short:'법령', section:'법령'} ]
```
- 각 case 에 `page` 필드가 있다(`'std-constitution'` … `'ccourt'`). 표준판례는 **과목별로 독립된 페이지**이며 각 페이지가 자기 목차(편/장)를 가진다. "표준판례 안에서 과목 고르기"는 없다.
- 라우팅: `#/<pageId>` · `#/<pageId>/<caseId>` · `#/laws/<lawId>` · `#/laws/<lawId>/<versionId>` · `#/bookmarks`.
- 페이지 전환 UI는 8개를 모두 담되 section(표준판례 / 최근 판례 / 법령)으로 묶어 보여 준다. 모바일에서는 `short` 라벨.

## 2. 판례 열람 = 시트 (두 시안 공통)
- 목록에서 판례를 누르면 **페이지가 바뀌지 않고** 열람 시트가 열린다. 목록(차례)은 그 자리에 남고 스크롤 위치가 유지된다.
  - ≥1024px: 오른쪽에서 열리는 시트(폭 680px, 최대 60vw), 뒤 내용은 흐리게·클릭 시 닫힘, Esc 닫힘.
  - <1024px: 전체 화면(현재 B처럼). 상단에 닫기(←) 버튼.
- 시트 안: 헤더(제목·공식 사건명·인용표시+휘장·결과 배지·북마크·인용 복사) → 탭 4개 → 본문 → 이전/다음.
- **탭 순서(고정)**: `판시사항·요지` | `판결문 전문`(헌법재판소는 `결정문 전문`) | `참조조문·판례` | `메모`
  - `참조조문·판례` 탭 = 심판대상조문(있을 때) → 참조조문 → 참조판례 → **관련 판례**(참조조문이 겹치는 판례).
  - 판시사항·요지 탭에는 참조조문을 두지 않는다(옮긴 것).
- 섹션 제목("판시사항", "판결요지"/"결정요지", "심판대상조문", "참조조문", "참조판례", "관련 판례", "나의 메모")은 **보라(--accent-ink), 고딕**. 로마숫자/번호 장식은 선택.
- "이어 읽기"(마지막 읽던 판례 복원, `lawbook:last`) 기능은 **삭제**. 북마크·메모·설정만 저장.

## 3. 판결문 전문 조판 (중요)
`fullText` 블록을 렌더할 때:
1. 짧은 머리 블록(피고인·상고인·변호인·원심판결·청구인·당사자 등: 한 줄, 160자 이하, 주문·이유·전문 제외)은 `【피 고 인】  피고인` 처럼 **한 줄에 라벨(고딕)+내용(명조)**.
2. 【주 문】【이 유】 등은 고딕 소제목(보라).
3. 본문은 **문단 사이 0.75em 간격**(바투 붙이지 않는다). 줄바꿈 하나 = 문단 경계로 본다.
4. **개요 수준 소제목 인식**: 아래 패턴의 줄이 **40자 이하이고 문장종결("다." "함." 등)로 끝나지 않으면** 소제목으로 렌더(고딕 세미볼드, 위 여백 1.4em, 아래 .4em):
   - 1수준 `^\d+\.\s` (예: `1. 사건의 개요와 쟁점`) → 15.5px
   - 2수준 `^[가-힣]\.\s` (예: `가. 공소사실의 요지`) → 15px
   - 3수준 `^(\(\d+\)|\d+\)|[①-⑳])\s` (예: `1) 상고이유`, `(1) …`) → 14.5px
   - `[다수의견]` `[별개의견]` `[반대의견]` `[보충의견]` 로 시작하는 줄과 `^(대법관|재판관|대법원장)\s.+(의견|意見)$` 줄도 2수준 소제목.
   그 외 번호로 시작하는 긴 줄은 본문 문단(명조)이며 번호는 들여쓰기(hanging indent)로 처리한다.
5. 【이 유】 본문 문단은 `text-indent:1em` 권장(소제목·번호 문단 제외). 명조, `--fs`, line-height 1.9.
6. 마지막 줄(대법관 명단 "대법원장 조희대(재판장) …")은 작은 고딕으로.

## 4. 인용표시 — "법원 선고일자 사건번호 판결/결정"
- 모든 곳에서 `case.citation` 전체를 쓴다: 목록 항목, 카드, 시트 헤더, 관련 판례, 검색 결과, 북마크 목록, running head.
  예) `대법원 2026. 7. 22. 선고 2022도5937 전원합의체 판결`, `헌법재판소 2026. 7. 23. 선고 2026헌라3 전원재판부 결정`, 법원 결정은 `대법원 2026. 7. 22.자 2022마1234 결정`(데이터에 이미 반영).
- **금지**: `대법원 2022도5937 · 2026. 7. 22.` 같은 임의 축약. 폭이 정말 부족한 곳(칩, 28자 이하로 줄여야 하는 한 줄)에서만 `case.citeShort`(`대판 2022도5937` / `대결 …` / `헌결 2005헌바19`)를 쓴다.
- 제목과 인용표시가 붙어 보이는 곳이 없어야 한다: 목록·관련 판례·검색 결과에서 **제목 줄과 인용 줄을 분리(block)** 하거나 최소 12px 간격. 첨부 이미지(관련 판례에서 제목과 사건번호가 붙은 것)의 문제를 모든 목록에서 검토한다.

## 5. 법령 페이지 (`#/laws`) — 공통 모듈 사용
- `spec/laws-module.html` 의 `<style id="laws-css">` 와 `<script id="laws-js">` 를 **그대로 복사**해 넣고, 데이터 자리 `<script id="laws-data" type="text/plain">__LAWS_DATA_B64__</script>` 를 둔다(`tools/build.py` 가 채움). 모듈 API 는 그 파일 머리 주석 참조. 모듈 CSS 는 손대지 말고(변수만 공유), 호스트 레이아웃만 만든다.
- 구성: **법령 목록(그룹별, 헌법이 첫 번째)** + **선택한 법령의 목차 트리** + **조문 본문**. 모듈이 세 영역을 각각 렌더한다(`LawsModule.render({lawId, versionId, headEl, tocEl, textEl, onChange})`). 기본 선택 = `constitution`.
- 헌법은 머리 부분에 **개정이력 선택**(모듈이 `<select>` 로 그려 줌)이 있고, 선택 시 `onChange` 로 라우트를 `#/laws/constitution/<versionId>` 로 갱신한다.
- 조문 본문은 명조, 조문 번호·제목·편장절·목차는 고딕(모듈 CSS 가 처리). 조문 바로가기·이 법령에서 찾기도 모듈이 처리.
- 데이터는 법령 페이지를 **처음 열 때** `LawsModule.load()` 로 푼다(약 1.4MB base64 → 5.7MB JSON, 수백 ms). 푸는 동안 "법령 데이터를 준비하는 중…" 한 줄. 실패하면 오류 문구 표시.
- design-d: 데스크톱은 왼쪽 열(법령 목록 → 목차)과 오른쪽 본문(최대 폭 760px). 모바일은 상단에 법령 선택 `<select>`(그룹별 optgroup) + "목차" 버튼으로 슬라이드-인 패널.
- design-e: 왼쪽 사이드바에 법령 목록(그룹) → 선택한 법령 아래 목차 트리. 본문은 가운데 열.
- 전역 검색은 판례만 대상으로 해도 된다(법령은 모듈의 "이 법령에서 찾기" 사용).

## 6. 휘장
- `spec/emblems.html` 의 `<style id="emblem-css">` 를 복사하고, 법원 아이콘 자리를 `<span class="court-ic scourt" role="img" aria-label="대법원"></span>` / `<span class="court-ic ccourt" role="img" aria-label="헌법재판소"></span>` 로 바꾼다(이전의 `<svg><use href="#ic-…">` 와 symbol 정의는 삭제). 인용표시 줄에서는 22~24px, 목록에서는 18~20px. 흑백 처리된 상태로 둔다(색 입히지 않음).

## 7. 시안별 구조
### design-d — "판례집+시트"
- design-b 그대로: 상단 바(브랜드 · 페이지 탭 · 검색/북마크/테마/설정), 가운데 한 열(최대 720px), 미색 배경, 차례(dotted leaders) 기반 목록, 라틴어 격언 1개.
- 페이지 탭: 데스크톱은 한 줄에 8개를 section 구분자(작은 세로선/여백)와 함께. 모바일은 가로 스크롤 탭 + `short` 라벨. (≥860px 에서 section 이름을 작은 글씨로 탭 위에 둘 수도 있음.)
- 판례는 §2 시트로 연다. 왼쪽 슬라이드 패널(목차)은 유지하되, 현재 페이지의 목차 + 다른 페이지로 가는 링크를 담는다.
### design-e — "서가"
- 왼쪽 고정 사이드바(폭 280~300px, ≥1024px): 상단에 페이지 목록을 section 별로(표준판례 › 헌법/행정법/민법/형법, 최근 판례 › 주요판례/전원합의체/헌법재판소, 법령), 그 아래 **현재 페이지의 목차 트리**(표준판례: 편→장→판례; 주요판례: 과목→판례; 전원합의체·헌법재판소: 월→판례; 법령: 법령 목록→목차). 사이드바는 자체 스크롤.
- 가운데 열은 design-b 의 종이·조판(차례 목록 / 빈 상태). 판례는 §2 시트로 연다(사이드바는 그대로 보임; ≥1400px 에서는 시트를 오버레이 대신 오른쪽에 도킹해 3열로 보여도 좋다).
- 모바일: 사이드바는 왼쪽 드로어(햄버거), 하단 바(목차 · 검색 · 북마크 · 설정).

## 8. 검수 기준 (v1 §10 + 추가)
- 45건 × 4탭 × 2뷰포트 오류 0, 가로 스크롤 0.
- 법령 페이지: 헌법(현행·구 판본 1개), 민법, 형법, 공직선거법을 열어 오류 0, 조문 바로가기 동작(예: 민법 제750조), 목차 클릭 이동 동작.
- 템플릿 안에 "헌재"/"전합" 없음, `lawbook:last` 없음, "이어 읽기" 없음, "대법원 20xx도… · 날짜" 식 축약 없음.
- 스크린샷으로 확인: 목록(제목/인용 분리), 시트(4탭), 전문(소제목·문단 간격), 참조조문·판례 탭(관련 판례 간격), 법령(헌법 개정이력·민법 조문), 모바일 전체화면 시트, 다크 모드.
