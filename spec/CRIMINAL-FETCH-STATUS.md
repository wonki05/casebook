## 수집 방식과 모델 사용
- **law.go.kr 수집은 모델이 필요 없다.** 민법과 같이 `tools/fetch_unit.py run`(청크 수집 → 실패 재시도 → 검사 → 커밋) 뒤 `resolve`(한글주소 조회 실패 건을 사건번호·선고일이 모두 일치할 때만 검색으로 수집)를 7개 worktree 에서 동시에 돌렸다. 모델 토큰은 쓰지 않았다.
- 판단이 필요한 단계에만 저가 모델을 읽기 전용(저장소 쓰기 없음, 결과는 JSON 파일로만)으로 썼다.
  - Sonnet 5.5 medium ×1 — 미게재 11건의 원인 분류(검색 도우미 사용): `data/standard-cases/_reports/fetch-criminal-miss-triage.json`
  - Haiku high ×3 — crosscheck low-similarity 115건 중 스크립트(책 판결요지의 10글자 조각이 공식 전문에 든 비율 0.95 이상 71건)가 걸러내고 남은 44건의 "같은 재판의 표기 차이 / 범위 차이 / 다른 재판" 1차 판정: `data/standard-cases/_reports/crosscheck-criminal-fetch-review.json`
  - 사용자 제공본 9건의 검수(아래): Workflow 2회, agent 91개(Haiku high·Sonnet medium·Sonnet high): `data/standard-cases/_reports/provided-text-review-criminal.json`
  - 모델 판정 중 영향이 큰 것은 사람이 원자료·재검색·확대 대조로 다시 확인했다.

- **화면 우선순위(사용자 지시)**: 쟁점·판결요지는 표준판례가 우선이고, 표준판례에 없는 필드(참조조문·참조판례 등)만 제공본으로 보충한다(`fieldSources` 의 `supplemental`). 출처 표기는 "판례 검색 사이트(케이스노트) 수록본 · 사용자 제공" 등 제공 형태를 그대로 쓰며 "국가법령정보센터"·"공식"으로 표시하지 않는다(`fieldSources`·출처 줄을 브라우저로 확인).
- **판결 본문만 보존**: 판시사항·판결요지·참조조문·참조판례·사건 표(사건·피고인·상고인·변호인·원심판결·판결선고)·주문·이유·재판부 서명. 소송경과·인용판례·유사판례·주석서 인용·인용 문헌·회사 정보·이용자(기관·이름) 표시와 "많이 하이라이트된 문장 표시" 는 버렸다.
- **글자는 바꾸지 않았다**: 빈 줄·줄 끝 공백 정리, 표로 갈라진 재판부 서명을 한 사람 한 줄로 합침, 쪽 나눔으로 끊긴 낱말 1곳(440: "주고받았다/고 하더라도")을 이음 외에 손대지 않았다. 원문의 오탈자·특이 부호(예: 317 의 `○○동 빌딩`의 백틱, 440 의 `흔글(ⅧP)`, 175 의 "시울고등법원")도 그대로다. 정제 도구가 원문과 정제본이 공백을 뺀 글자 단위로 같은지 스스로 대조한다.
- **원문 추출**: 사용자 메시지를 세션 기록에서 프로그램으로 꺼내 건별 원문 파일을 만들었다(손으로 옮기지 않아 옮겨 적기 오류가 없다).
- **검수**: 정제본 8건 × 3관점(버린 부분에 판결문이 섞였나 · 남은 부가정보 · 구조·등록부 일치) + 지적마다 반박 검증 2회. 판결문 자체의 문제는 없었고(지적은 검수용 라벨 또는 보존해야 할 원문 특성), 등록부와의 일치(법원·선고일·유형·사건번호·전원합의체)는 가져오기 도구와 `audit` 가 기계적으로 확인했다.

### 88도650 (스캔 PDF) 판독
- PDF 는 글자 층이 없는 이미지다(Windows 한국어 OCR 은 도트 글씨를 읽지 못해 버림). 독립 판독자 3명이 쪽별로 옮기고, 이견 낱말만 확대(600~1000 dpi)·글자 모양 수치 대조로 정했다. 확정: `(증제1호)`·`(증제2호)`(여는 괄호 앞 간격 있음), `수회`, `이새키 카불면`(ㅋ 이 인쇄됨), `등`(둥 아님), 줄 끝 낱말 이음(원|심은 → 원심은 등).
- 책(standardSource) 발췌와 540자를 대조하니 1자 차이뿐이다 — 책이 "뇌진탕등으로 **인하여** 정신을 잃고"에서 "인하여"를 뺐다(스캔에는 있음, `standardSource` 는 그대로).
- 확정한 최종 전사본을 다른 독립 검증자 14 agent 가 이미지와 줄 단위로 재대조했다. 남은 이견: `시능을`("시늉"의 오기로 보이나 인쇄된 모양이 능에 가까워(글자 모양 유사도 0.73 대 농 0.54) 인쇄된 대로 옮김), `찔것같은`의 `찔`(잉크가 번져 판독 불가 — 문맥에 따른 최선의 읽기). 두 곳은 `sourceNote` 에 불확실로 적었다.
- 줄 끝 여백의 회색 상자(2쪽 주문 줄·3쪽 복부를 뒤·4쪽 직접 뒤·5쪽 구금 뒤)와 1쪽 머리 오른쪽·6쪽 위와 가운데 상자는 문장이 상자 없이도 이어지므로 글자를 가린 것이 아니라고 보고 제외했다. 줄 안에서 이름·주소를 가린 상자는 `▒▒▒` 로 두었다.
- **공개 배포 전 확인**: 출력본 머리에 "영리목적으로 이용하거나 무단 배포를 금합니다" 안내가 있다. 이 PDF 본문을 GitHub Pages 에 공개하기 전에 이용 조건을 확인해야 한다(`sourceNote` 에도 적음).

### 새로 추가한 도구
- `add_cases.py remove <id> --into <남길 id>` — 같은 과목·같은 제목·같은 목차 위치·같은 법원/선고일/유형이고 사건번호가 서로의 병합번호에 들어 있는 **중복 배치만** 정리한다. 지우는 항목의 재판 ID·배치 id 를 남기는 항목의 재판 ID 로 `identityAliases` 에 이어 두고(개인 메모·북마크가 따라가도록), 남기는 항목에 공식 수집본이 있을 때만 지우는 항목의 수집 파일을 함께 지운다(공식 텍스트를 잃지 않도록). 지울 항목에만 `standardSource` 가 있거나 제목·목차가 다르면 거절한다. 시험: `tools/test_remove_placement.py`.
- `build_data.display_case_number` — 헌법재판소가 아닌 법원의 사건번호에서 등록부 내부 표기 "(병합)" 을 화면용에서 뗀다(시험: `tools/test_identity.py`).
- `tools/provided_text.py parse|import` — 사용자 제공 판결문 텍스트를 판결 본문만 남겨 정제하고(원문과 글자 단위 자체 대조), 등록부의 법원·선고일·유형·사건번호·전원합의체와 인용문을 대조·사이트 부가정보 문구 검사 후 `fetched/<id>.json` 으로 저장한다. 시험: `tools/test_provided_text.py`.

## 검증
- `make validate`: 오류 0 (3,388건 점검, 경고 1,104건 — 아직 수집하지 않은 다른 과목과 형법 426).
- `make data`: 3,388건, 전문 2,278건(+9). `make laws build web` 성공.
- `make webcheck`: 전문 해시·경로·메모 이관·서비스 워커·오프라인·잘못된 갱신 거부 등 13개 항목 모두 통과(이번 실행은 첫 시도에 통과). 앞선 174 정리 직후의 실행에서는 오프라인 저장 단계(전문 2,000여 개 내려받기)가 60초 제한을 넘어 한 번 시간 초과로 실패했고 `webcheck` 만 다시 돌려 통과했다 — 자료 결함이 아니라 시간 제한 문제로 판단한다.
- **형법 전수 열람 확인**(HTTP 로 서비스한 `output/web` 을 Playwright 로, 일회용 스크립트): 504건 배치를 `#/std-criminal/<id>` 로 모두 열어 제목·요약이 나오고, 전문이 있는 503건은 전문 탭 첫 구절이 화면에 나오며, 제공본 9건은 자기 출처 표기("공식" 아님)가 보이고, 목록 페이지에 504줄이 보이고, 페이지 오류가 없음을 확인했다. 전문이 없는 것은 426 뿐이다. 88도650·2018도2738 은 스크린샷으로 모양도 확인했다.
- 공식 인용문 ↔ 등록부 메타 대조(`fetch_unit.py audit`): 전문 503건(공식 494 + 제공 9) 중 표시 12건은 모두 헌법재판소·법원명 약칭 형식 차이 11건과 날짜 1건(30, 사용자가 등록부 유지로 결정)이며 제공본 9건은 표시 없음.
