## 이미지 생략 정책 (적용: 24건, 이미지 70개)

- law.go.kr 본문의 `<img>`(수식·표·그림)는 글자로 옮길 수 없으므로 텍스트만 수집하고 공식 문자열 사이에는 아무 표식도 끼우지 않는다.
- 수집 기록 `fetched/<id>.json` 의 `retrieval`(`method: law.go.kr-page`, `omittedImageCount`, `omittedImages[{section, offset, before, src, alt}]`, `note`)에 생략한 이미지의 구역·위치(구역 글자 앞쪽의 공백 아닌 글자 수와 앞 20자)·이미지 경로를 남긴다. 이미지가 없으면 `retrieval` 을 쓰지 않는다.
- 위 표의 비고에 건별 개수와 구역을 적었다. 화면 안내문은 템플릿을 고치지 않고 이 메타데이터만 남겼다(`retrieval.omittedImageCount > 0` 이면 안내를 띄울 수 있다).
- 판례검색 수록본은 이미지 자리의 표·그림을 글자로 가진 것으로 보이는 건이 있다(이유가 law.go.kr 보다 길다: 2015헌라7 +12,557자, 2019헌마288 +1,700자, 2016헌마86 +1,317자, 2018헌마405 +1,208자 등). 어느 출처를 우선할지는 정하지 않았고 후속 판단 사항이다.

## 선고일 충돌: 2018헌마456

- 등록부·헌법재판소 목록: 2021-01-28. 표준판례 배치(`std-constitution-128`)도 2021-01-28.
- law.go.kr(detcSeq 163493): API `종국일자 20210126`, 페이지 인용문 `[전원재판부 2018헌마456, 2021. 1. 26.]`. `std-constitution-128.json` 이 이 페이지본이며 인용문 날짜가 등록부와 달라
  `fetch_lawgo.py` 의 선고일 검사(`선고일 불일치`)와 build 의 같은 재판 공유 검사(`fetched_citation_matches_record`)가 통과하지 않는다. 그래서 `ccourt` 배치는 전문이 없었다.
  결정문 본문(이유)에는 선고일이 적혀 있지 않고 재판관 서명뿐이다.
- 헌법재판소 판례검색: 종국일자 2021. 1. 28., `헌재 2021. 1. 28. 2018헌마456등, 판례집 33-1, 32`, 판례집 수록본 첫 줄 `[2021. 1. 28. 2018헌마456, 2020헌마406, 2018헌가16(병합)]`. 같은 사건의 결정해설집·최근 주요결정 게시물도 2021년 1월 28일로 적는다.
- 판단: 선고일은 2021-01-28 이고 law.go.kr 의 2021-01-26 은 law.go.kr 쪽 종국일 표기로 본다. 등록부(`--date`)는 수정하지 않았다. 자동 병합도 하지 않았다.
  `cc-2018heolma456` 에는 선고일이 등록부와 일치하는 판례검색 판례집 수록본(33-1)을 저장했다. law.go.kr 페이지본(`std-constitution-128`)은 그대로 둔다.
  law.go.kr 페이지본을 `ccourt` 배치와 연결하려면 날짜 불일치를 정리하는 사용자 판단이 필요하다.

## 남은 문제와 후속 판단 사항

1. **2020헌바318 구역 제목 중복**: law.go.kr 페이지와 판례검색 공보 345호 수록본 모두 이유 구역 제목이 `【주 문】` 으로 두 번 나온다(둘째가 이유 본문, `1. 사건개요` 로 시작). 공식 원문 그대로 보존했다. 제목 정정은 사용자 승인 후 `tools/apply_fulltext_corrections.py` 로만 한다.
2. **이미지 24건**: 위 정책대로 글자만 보존했다. 판례검색 수록본과 어느 쪽을 쓸지(특히 2015헌라7 이미지 19개) 후속 결정이 필요하다.
3. **law.go.kr 미게재 4건**: 2024헌마990, 2025헌가7, 2022헌가28, 2024헌마569 는 판례검색 수록본이다. law.go.kr 이 게재하면 `python -X utf8 tools/fetch_lawgo.py --id <id> --force` 로 공식본으로 바꾼다(`korean-law` API 와 한글주소 모두 아직 결과 없음).
4. **재판관 서명 줄**: law.go.kr 페이지 수집본에는 이유 끝의 재판관 서명 줄(과 일부 별지)이 없는 건이 있다. 판례검색에는 있다(2018헌마1067·2022헌바95 는 서명 줄 57자, 2018헌바407·2017헌가22·2014헌마888·2017헌마643 등은 서명·별지 수백~천여 자).
   지난 보고서의 `본문 종결부 확인 불가` 4건(2018헌마1067·2019헌마656·2019헌마825·2022헌바95)은 페이지 본문이 API 응답과 글자가 같고 판례검색 이유와의 글자 수 차이도 26~57자로 작아, 본문이 잘린 흔적은 없다(서명 줄·표기 차이).
5. **결정문 수록본의 단락 끊김**: 판례검색 `결정문` 형식(2024헌마990, 2025헌가7, 2022헌가28)은 쪽 경계에서 문장이 단락으로 갈라진 곳이 있다. 글자는 바꾸지 않았다(조판 정리는 별도 판단).
6. **판례검색 대조 실패**: 이미지 건 중 2016헌바55, API 잘림 건 중 2022헌바238 은 판례검색 상세창 시간 초과로 대조하지 못했다(이 두 건의 law.go.kr 수집 자체는 API 응답과 일치).
7. **범위 밖 관찰**: `cc-2023heolba47.missing.json` 은 같은 id 의 공식 수집본(`cc-2023heolba47.json`)이 이미 있는데 남아 있는 옛 기록이다(이 세션 대상 아님, 그대로 둠).
8. **웹 검사**: 아래 검증 절 참조.
9. `fetch_lawgo.py` 는 다른 세션(줄바꿈·개요 복구)도 고치는 파일이다. 이 세션의 변경은 이미지 위치 기록, `apiSeq` 힌트, 실패 기록 보존으로 한정했으니 병합 시 해당 함수 근처 충돌만 확인하면 된다.
